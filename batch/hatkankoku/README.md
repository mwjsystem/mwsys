# 発注勧告（【原本】YYYY年MM月発注勧告.xlsm）の新システム版

旧システム（Oracle）に直接つないでいた Span マクロを、新システムの画面「仕入関連 → 発注勧告」（`/frmkankoku`）と組み合わせて使う。
xlsm のシート・式・ボタンはそのまま使い、Module1 だけを差し替える。

## 毎月の手順

1. 今月の発注勧告.xlsm を開く（C1 に今日の日付が入る）。
2. 画面「発注勧告」で基準日（C1 と同じ日）を確かめ、その xlsm を選ぶ。
   「発注勧告データ.xlsx を出力」で `発注勧告データ_yyyymmdd.xlsx` を保存する。
3. xlsm の発注シートで Span を実行すると、ファイルを選ぶ画面が出るので、2 のファイルを選ぶ。
   基準日が C1 と違うときは確認が出る。
4. 発注数などを決めて、Make_data で data シートを作り、xlsm を保存する。
5. 画面「発注勧告」で xlsm を選び直し、「② 発注伝票の登録」で内容を確かめて「発注伝票を登録」。
   仕入先・倉庫（【関東倉庫】は 016、それ以外は 01）・発注日ごとに発注伝票ができる（メモ「発注勧告から作成」）。
   同じ発注日に発注勧告から作った伝票があると、確認のチェックを入れるまで登録できない。

## Module1 の差し替え

1. xlsm を開き、Alt+F11 で VBA の画面を開く。
2. 標準モジュールの Module1 を右クリック →「Module1 の解放」（エクスポートは「いいえ」でよい）。
3. 「ファイル → ファイルのインポート」で `Module1.bas`（このフォルダ。文字コードは Shift_JIS）を取り込む。
4. 【原本】として保存する。ボタンに割り当てたマクロ名（Span・Make_data・Save_csv）は変えていない。

## 現行からの変更点

- DB に接続していた関数（get_zaiko・get_jyuzan・get_jznall・get_hattyuzan・get_shukka・get_hatz・get_inday）は、データ.xlsx の値を返す。
- 受注残は、新システムで「今日まで・全期間 の大きい方」を計算済み。01 の商品は 01 と 001 の受注残の合計を引く。
- 2019-06-28 より前の発注（古い移行データ）は、発注残・発注数・最短入荷日に入れない（在庫・発注チェックと同じ）。
- Save_csv（通販プロの 発注取込.csv）は使わない。実行すると、画面で登録するよう案内が出る。
- 発注伝票の原価は、発注日より前の最新の単価マスタ。入荷予定日は data シートの入荷予定日（予定）。

`db/20261124_hatkankoku.sql`（fsyukscm・fhatzall）と、`db/20261124_chusyutsu.sql` の fzaikosc。
